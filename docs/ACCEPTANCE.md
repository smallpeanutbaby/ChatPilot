# ChatPilot 验收标准

每条标准都写明验证方式：

- **自动**：`dotnet test` 里有对应的测试，测试名写在括号里
- **本机**：在本机用测试通道 + 隔离的 herdr 会话实测
- **人工**：需要你用手机微信操作

只有自动和本机两类都通过，才算可以交付；人工项列出步骤，由你在手机上确认。

## 一、构建和质量

| 编号 | 标准 | 验证 |
|---|---|---|
| Q-01 | `dotnet build` 零警告零错误（警告视为错误） | 本机 |
| Q-02 | `dotnet test` 全部通过 | 本机 |
| Q-03 | Server 和 Node 都能发布成 osx-arm64、win-x64、linux-x64 单文件程序 | 本机 |
| Q-04 | 所有项目开启可空引用检查，没有用 `!` 压制空引用警告的地方 | 审查 |

## 二、功能

### 设备配对和连接

| 编号 | 标准 | 验证 |
|---|---|---|
| F-01 | `/pair` 返回 8 位配对码、有效期、服务器证书指纹和可以直接复制运行的节点命令 | 自动（`Pair_command_returns_code_and_instructions`） |
| F-02 | 节点 `pair` 命令用正确的配对码拿到设备令牌，并写入配置文件 | 自动 + 本机 |
| F-03 | 节点 `run` 后，`/devices` 显示该设备在线；节点退出后显示离线 | 自动 + 本机 |
| F-04 | 服务器重启后节点自动重连，不用重新配对 | 本机 |
| F-05 | `/unpair <设备>` 后，该设备立即断开，旧令牌不能再连接 | 自动 |
| F-06 | 同一台设备重复连接时，旧连接被新连接替换 | 自动 |

### 指令

| 编号 | 标准 | 验证 |
|---|---|---|
| F-10 | `/ls` 按设备分组列出 agent：序号、名字或工作区、类型、状态 | 自动 + 本机 |
| F-11 | `/use <设备>` 切换默认设备；设备不存在时给出可选列表 | 自动 |
| F-12 | `@<目标> 内容` 能按序号、名字、pane ID、工作区名（不区分大小写）找到 agent，并且立即回复"已发送" | 自动 + 本机 |
| F-13 | 目标有歧义（多个匹配）或找不到时，返回明确提示，不会发错 | 自动 |
| F-14 | `设备/目标` 前缀能指定设备；设备离线时提示离线 | 自动 |
| F-15 | agent 做完后，它的最后一条回复推回聊天，超过 4000 字自动分段，最多 4 段，超出部分截断并提示；claude、codex、pi、kimi、qwen、opencode、kilo、droid、cursor、copilot、grok 读会话记录，其他类型读终端 | 自动 + 本机 |
| F-16 | agent 卡在审批时推送"需要确认"和屏幕摘要；`/yes`、`/no` 能处理；`/yes` 认得各家 agent 竖排选项的选中标记，只选"这一次同意" | 自动 + 本机 |
| F-17 | `/read <目标> [行数]` 返回最近的终端输出，行数限制在 1–500 | 自动 + 本机 |
| F-18 | `/new <目录>` 在白名单目录里新建 herdr 工作区并启动 agent（默认 claude，可选 herdr 支持的全部类型和自定义启动方式），返回 agent 名字；可以指定设备、类型、名字 | 自动 + 本机 |
| F-19 | `/keys` 只接受白名单内的按键，`/name` 校验名字格式 | 自动 |
| F-20 | 不是指令的文字交给当前设备的 `butler`；没有管家时提示用 `/butler` 创建 | 自动 |
| F-21 | `/butler` 在设备上创建名为 butler 的 agent，并告诉它怎么用 herdr | 本机 |
| F-22 | 指令写错时返回用法提示，不会崩溃 | 自动 |
| F-23 | 节点执行超时（默认 30 秒）时，聊天里收到超时提示，服务器不会卡住 | 自动 |

### 微信通道

| 编号 | 标准 | 验证 |
|---|---|---|
| F-30 | 首次启动或执行 `login` 时，终端显示二维码并保存 PNG；扫码确认后保存 bot token 和主人的微信号 | 自动（模拟 iLink）+ 人工 |
| F-31 | 处理二维码过期刷新（最多 3 次）、IDC 重定向、需要输入验证码这几种状态 | 自动（模拟 iLink） |
| F-32 | 长轮询收到主人的文字消息后执行指令并回复，回复带上该消息的 context_token | 自动（模拟 iLink） |
| F-33 | 同步游标持久化，重启后从上次的位置继续 | 自动 |
| F-34 | 接口返回 -14（token 失效）时暂停 1 小时；连续 3 次失败退避 30 秒 | 自动 |
| F-35 | 消息里的大整数 ID 不丢精度 | 自动 |
| F-36 | 你在手机上能完成：扫码绑定 → `/devices` → `/ls` → `@agent 指令` → 收到回复 | 人工 |

### 第二期：更顺手、能力更多

| 编号 | 标准 | 验证 |
|---|---|---|
| F-40 | `/read`、`/last`、`/diff`、`/stop` 不写目标时用"最近打过交道的 agent"（最近给你发过通知、或你最近指定过的）；从来没有时提示写目标 | 自动 |
| F-41 | `/re 内容` 把内容原样交给最近打过交道的 agent | 自动 |
| F-42 | `/yes`、`/no` 不写目标时：只有一个 agent 在等确认就用它；有多个时列出来让你指定，不按任何键 | 自动 |
| F-43 | agent 正在干活、或者已经有任务在跟踪时，`@目标` 发来的指令排队（每个 agent 最多 10 条），回复"已排队（第 N 条）"；它空闲后按顺序逐条发出，每条做完各通知一次，通知里说还有几条在排队；节点重启后排队的指令还在；agent 不见了时丢掉整个队列并通知 | 自动 |
| F-44 | `/stop` 清空排队的指令；agent 在干活时按 Esc 打断，在等确认或空闲时不按键 | 自动 |
| F-45 | `/close 目标` 先回复要关闭的是哪个 agent，2 分钟内 `/close 设备/目标 确认` 才关闭它所在的 pane；确认对不上（过期、换了目标）时只重新给出说明 | 自动 |
| F-46 | `/watch 目标`、`/watch all [设备]` 之后，不是通过 ChatPilot 派的活做完、或者卡在确认框时也会通知；通过 ChatPilot 派的活不会重复通知；`/watch` 列出在盯谁，`/unwatch` 停止；设置在节点重启后保留 | 自动 + 本机 |
| F-47 | `/diff [目标]` 返回 agent 工作目录的分支、未提交的改动、改动行数统计、最近 3 次提交；`/diff 目标 文件` 返回这个文件的 diff；目录不是仓库、没装 git 时给出明确提示 | 自动 |
| F-48 | 先发图片（微信或 Telegram），再 `@目标 内容`，图片会一起交给 agent：节点把图片存到 agent 工作目录的 `.chatpilot/attachments/`，在指令后面附上路径；不是图片、太大、超过 4 张时给出提示；`/drop` 丢掉还没发的图片 | 自动（模拟 iLink / Telegram）+ 人工 |
| F-49 | `/pending` 列出在等确认的 agent（带 `/yes` 写法）、在干活的 agent（干了多久、排了几条）、定时任务数、暂存的图片数 | 自动 |
| F-50 | `/history [条数]` 列出最近做完 / 出错的任务（时间、设备、agent、耗时、任务摘要、结果摘要），以及今天的数量和总耗时；服务器重启后保留 | 自动 |
| F-51 | `/wake 设备` 让同一网段里在线的其他设备广播 Wake-on-LAN 唤醒包（MAC 地址来自那台设备上次上线时的报告）；对不上网段时让所有在线设备都试一次；在线、不知道网卡、没有其他在线设备时给出提示 | 自动 + 人工 |
| F-52 | `/at 时间 内容` 定时派活：支持 `23:00`（已过就是明天）、`明天 9:00`、`30m`、`2h`、`1h30m`、`45分钟`；时刻按配置的时区（`TimeZone`）计算并在回复里写明；`@序号` 在定时的时候就换成名字；`/at` 列出、`/at del 编号` 取消；到点执行并推送结果；服务器停机错过超过 10 分钟的不执行，只通知 | 自动 |
| F-53 | 可选的 Telegram 通道：只处理配置的主人私聊发来的文字和图片（图片的说明文字当成指令执行）；offset 先保存再处理；主动通知同时发到微信和 Telegram | 自动（模拟 Telegram）+ 人工 |

## 三、安全

| 编号 | 标准 | 验证 |
|---|---|---|
| S-01 | 不是主人的微信号发的消息一律不处理、不回复 | 自动 |
| S-02 | WebSocket 不带令牌或令牌错误返回 401，不会升级连接 | 自动 |
| S-03 | 配对码只能用一次；过期后失效；错误的配对码返回 401 | 自动 |
| S-04 | 配对接口按 IP 限流（每分钟 5 次），超出返回 429 | 自动 |
| S-05 | 服务器状态文件里只有令牌的哈希，没有明文 | 自动 |
| S-06 | 节点校验证书指纹，不一致时拒绝连接，也拒绝配对 | 自动 |
| S-07 | `/new` 拒绝白名单以外的目录，包括 `..` 路径穿越、符号链接跳出、相对路径、不存在的目录 | 自动 |
| S-08 | 指令文本里的 `;`、`$()`、反引号、引号、换行原样传给 agent，不会被当成命令执行 | 自动（检查进程参数数组） |
| S-09 | 节点只接受协议里定义的几种指令，未知类型直接报错 | 自动 |
| S-10 | agent 类型只能是白名单里的（herdr 支持的类型和配置的自定义启动方式） | 自动 |
| S-11 | WebSocket 单帧超过 1 MiB 时断开连接；指令文本超过 16 KB 时拒绝 | 自动 |
| S-12 | 测试通道默认关闭（404）；开启后只接受回环地址，并且必须带令牌 | 自动 |
| S-13 | 日志里不出现设备令牌、bot token、配对码明文（配对码只在回复给主人时出现） | 自动 + 审查 |
| S-14 | Unix 下节点配置和服务器状态文件权限是 600 | 自动 |
| S-15 | 没开 TLS 时，服务器只能监听回环地址，否则拒绝启动 | 自动 |
| S-16 | 协议版本不一致时拒绝连接 | 自动 |
| S-17 | `/diff` 只运行只读的 git 命令，关掉外部 diff、文本转换、fsmonitor（仓库配置的 clean 过滤器除外，见 SECURITY.md）；文件路径不能有 `..`、不能是绝对路径、不能以 `-` 开头 | 自动 |
| S-18 | `/close` 没有确认不会关闭任何东西；`/stop` 不会在确认框上按 Esc | 自动 |
| S-19 | `/wake` 只接受格式正确的 MAC 地址，节点除了广播唤醒包不做别的事 | 自动 |
| S-20 | 图片下载要带目标设备自己的令牌，别的设备拿不到；节点核对大小和 SHA-256，只保存真的图片，文件名由节点决定；微信图片地址只接受 https 的 `*.qq.com` | 自动 |
| S-21 | Telegram 只认配置的主人；bot token 不出现在日志里 | 自动 |
